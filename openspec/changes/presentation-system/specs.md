# Specs：簡報系統

## 1. 場地選擇（Venue Selection）

### 1.1 場地首頁
- **MUST** 顯示所有啟用中的場地卡片
- **MUST** 每張卡片顯示：場地名稱、目前進行中的場次（若有）、下一場場次時間
- **MUST** 點擊場地卡片進入該場地的議程頁
- **SHOULD** 卡片支援自訂強調色（由管理員設定）

**Scenarios:**
```
Scenario: 首頁顯示所有啟用場地
  Given 系統中有 3 個啟用場地
  When 使用者造訪首頁
  Then 顯示 3 張場地卡片

Scenario: 首頁不顯示停用場地
  Given 系統中有 1 個停用場地
  When 使用者造訪首頁
  Then 該停用場地不出現在列表中
```

## 2. 場地議程（Venue Schedule）

### 2.1 議程列表
- **MUST** 依時間順序列出該場地所有場次
- **MUST** 每個場次顯示：主題、講師、開始時間、結束時間、狀態（未開始／進行中／已結束）
- **MUST** 進行中的場次有視覺高亮
- **MUST** 未開始的場次顯示倒數計時
- **MUST** 點擊場次後進行時間驗證

**Scenarios:**
```
Scenario: 顯示進行中場次高亮
  Given 現在時間為 14:05
  And 場次 A 時間為 14:00-15:00
  When 使用者查看議程
  Then 場次 A 顯示「進行中」狀態並有高亮樣式

Scenario: 未到時間場次不可進入
  Given 現在時間為 13:50
  And 場次 A 時間為 14:00-15:00
  When 使用者點擊場次 A
  Then 顯示「尚未開始」訊息並阻擋進入

Scenario: 已結束場次不可進入
  Given 現在時間為 16:00
  And 場次 A 時間為 14:00-15:00
  When 使用者點擊場次 A
  Then 顯示「場次已結束」訊息並阻擋進入
```

## 3. 簡報檢視器（Presentation Viewer）

### 3.1 進入驗證
- **MUST** 進入頁面時伺服器端驗證當前時間是否在場次時間內
- **MUST** 時間驗證在 Server Component / API Route 執行，不得僅依賴前端
- **MUST** 驗證失敗時重定向回議程頁並帶錯誤訊息

### 3.2 簡報展示
- **MUST** 以圖片方式逐頁顯示（img 標籤，但圖片 URL 須透過 signed URL 取得）
- **MUST** 提供上一頁／下一頁按鈕
- **MUST** 顯示目前頁數（第 X 頁 / 共 Y 頁）
- **SHOULD** 支援鍵盤左右鍵翻頁
- **MUST** 每 60 秒伺服器端重新驗證時間（場次結束時自動跳出）

### 3.3 防截圖防下載
- **MUST** 禁止右鍵選單（`contextmenu` event 攔截）
- **MUST** 禁止圖片拖曳（`dragstart` event 攔截）
- **MUST** 禁止文字選取（`user-select: none`）
- **MUST** 攔截 Ctrl+S、Ctrl+P、Ctrl+U 快捷鍵
- **MUST** 圖片上方疊加半透明浮水印（含場次 ID + 時間戳，每頁不同位置）
- **MUST** 視窗失去焦點（`blur`）時顯示黑色遮罩
- **SHOULD** 偵測 DevTools 開啟時顯示警告遮罩

## 4. 後台管理（Admin）

### 4.1 管理員認證
- **MUST** Email + Password 登入
- **MUST** 密碼以 bcrypt hash 儲存
- **MUST** Session 以 JWT 管理（NextAuth.js）
- **MUST** 未登入時所有 `/admin/*` 路由重定向至登入頁
- **MUST** 初始管理員帳號由環境變數種入

### 4.2 場地管理（CRUD）
- **MUST** 列出所有場地（含啟用狀態）
- **MUST** 新增場地：名稱（必填）、說明、強調色
- **MUST** 編輯場地資訊
- **MUST** 停用/啟用場地（不可硬刪除有場次的場地）

### 4.3 場次管理（CRUD）
- **MUST** 列出所有場次，可依場地篩選
- **MUST** 新增場次：場地（必填）、主題（必填）、講師、開始時間（必填）、結束時間（必填）
- **MUST** 開始時間必須早於結束時間（validation）
- **MUST** 編輯場次資訊
- **MUST** 刪除場次（同時刪除已上傳的簡報圖片）

### 4.4 簡報上傳
- **MUST** 每個場次可上傳多張圖片（PNG/JPG）
- **MUST** 上傳後圖片依序排列，可拖曳調整順序
- **MUST** 可單獨刪除特定頁圖片
- **MUST** 圖片儲存路徑不對外公開（需透過後端 signed URL 存取）
- **MUST** 上傳檔案大小限制：單張最大 10MB
- **SHOULD** 上傳時顯示縮圖預覽

### 4.5 管理員管理
- **MUST** 列出所有管理員帳號
- **MUST** 新增管理員（email + 初始密碼）
- **MUST** 刪除管理員（不可刪除最後一個管理員）
- **MUST NOT** 管理員可查看其他管理員的密碼

## 5. 即時廣播控制（Live Broadcast Control）

### 5.1 管理員廣播
- **MUST** 管理員後台的場次管理頁可進入「廣播模式」
- **MUST** 廣播模式中，管理員翻頁時所有連線中的觀看者自動同步到相同頁碼
- **MUST** 廣播模式可隨時關閉，關閉後觀看者可自由翻頁
- **SHOULD** 後台顯示目前連線觀看人數

### 5.2 觀看者接收
- **MUST** 觀看者進入簡報頁後自動建立 SSE 連線
- **MUST** 收到廣播訊號時立即切換至指定頁碼
- **MUST** SSE 斷線後自動重連（最多 5 次，間隔 2 秒）
- **SHOULD** 廣播模式啟用時，觀看者的翻頁按鈕停用（顯示「廣播中」提示）

### 5.3 技術實作（SSE via Edge Runtime）
- **MUST** 使用 Next.js Edge Runtime 的 `ReadableStream` 實作 SSE
- **MUST** 廣播狀態（是否啟用、當前頁碼）儲存於資料庫
- **MUST** 管理員推送頁碼時更新 DB 並透過 Redis Pub/Sub 或輪詢同步（視部署環境）

**Scenarios:**
```
Scenario: 廣播模式下觀看者同步翻頁
  Given 管理員已啟用廣播模式，目前在第 3 頁
  And 觀看者甲正在觀看第 1 頁
  When 管理員切換至第 5 頁
  Then 觀看者甲的畫面自動跳至第 5 頁

Scenario: 廣播模式關閉後觀看者可自由翻頁
  Given 管理員關閉廣播模式
  When 觀看者甲點擊下一頁
  Then 觀看者甲的頁碼正常前進，不受管理員影響
```

## 6. 非功能需求

- **MUST** 所有頁面 RWD 支援（桌面優先，但手機可正常瀏覽）
- **MUST** 深色主題，風格對標 2026summit.sat.cool
- **SHOULD** 首頁場地卡片使用 scroll 觸發動畫
- **MUST** 圖片的 signed URL 有時效限制（最長 1 小時）
